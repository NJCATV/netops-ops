# 代码与服务器同步约定

1. GitHub 的 `main` 与发布 tag 是代码、模板和文档的唯一事实来源；服务器不得长期保留未回传的手工代码。
2. 每台服务器的每个服务在部署清单中登记：仓库、分支/tag、部署目录、systemd/Docker 单元、健康检查和回滚 tag。
3. 运行时 `.env`、证书、密码、数据库、索引、日志和上传文件不与 Git 同步；只同步无秘密模板和变量名。
4. 紧急服务器修复必须在验证后立刻回传对应仓库，并在本仓库的变更记录注明影响、验证和回滚点。
5. 发布前执行模块构建与配置检查；发布后记录 `git rev-parse HEAD`、服务状态和健康检查。发现服务器版本与 tag 不一致即标记为漂移，先核对后修复。

每个模块后续会提供 `deploy/release-manifest.example.yml` 和只读漂移检查脚本，统一写入本仓库的版本清单。
